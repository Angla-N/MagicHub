## P0・安全与数据可靠性（必须先做）

### 1. 登录 token 只存内存，重启即全员掉线



* 位置：`apps/server/server.js:41-61`（`sessions` Map）

* 问题：服务器重启后所有客户端 token 失效，必须重新登录；无法横向扩容。

* 建议：token 改为**签名 JWT**（HMAC，密钥持久化到 `data/`），过期时间 7 天；服务端只校验不存储。

### 2. 登录 / 注册接口无限流，可被暴力破解与滥注册



* 位置：`server.js:484-506`、`user-store.js:99-121`

* 问题：无失败次数锁定、无验证码、无 IP 维度限流；注册接口可被脚本刷号。

* 建议：按 IP + 用户名维度做失败计数（5 次失败锁 15 分钟）；注册接口加简单人机校验（如图形 / 算术题）。

### 3. 上传文件（/uploads/）静态服务无鉴权



* 位置：`server.js:721-725`、`saveUploadFile`（`server.js:433-440`）

* 问题：文件消息的 URL 只要被猜到 / 泄露，任何未登录的人都能下载；头像 / 插件图标公开可接受，但**聊天文件应鉴权**。

* 建议：`/uploads/<id>` 改为带签名参数（如 `?token=` 或签名 URL），或整体对文件消息走登录态校验。

### 4. 上传文件无类型 / 内容校验 → 存储型 XSS 面



* 位置：`server.js:433-440`（`saveUploadFile` 只按扩展名落盘）

* 问题：可上传恶意 `.svg`（内嵌脚本）或 `.html`，经 `/uploads/` 分发后，若客户端用内联 /iframe 打开即执行。

* 建议：白名单扩展名（图片 / 常见文档）；SVG 上传后剥离 `<script>` 或转 PNG；静态服务对 html/svg 加 `Content-Disposition: attachment`。

### 5. CORS 全开 `*`



* 位置：`server.js:413-421`、`474-481`

* 问题：任何站点都可携带 Authorization 头跨域调用（配合 token 泄露即被利用）。

* 建议：生产环境 Origin 白名单（Electron file://、已知前端域名），其余拒绝。

### 6. 客户端本地插件 entry 路径未校验 → 可读任意本地文件



* 位置：`apps/desktop/main.js:68`（`localEntry: "file:///" + path.join(dir, entry)`）

* 问题：恶意插件 manifest 写 `entry: "../secret.txt"`，加载后 `file://` 直读任意文件。

* 建议：校验 entry 规范化后必须位于插件目录内（与后端 `resolvePluginPath` 同款防穿越）；加载前限制插件目录。

### 7. 插件上传解压无 zip 炸弹防护



* 位置：`server.js:136-147`（`extractArchive`）、`desktop/main.js:77-114`

* 问题：压缩包可解压出超大文件 / 海量文件，拖垮磁盘与 CPU。

* 建议：解压前设**文件数上限（如 200）与解压总大小上限（如 50MB）**，7za 解压后即时统计并清理超限包。

### 8. 演示账号硬编码进每个部署



* 位置：`user-store.js:20`（`demo/demo123`）

* 问题：每次全新部署都自带公开弱口令账号，可被他人登录滥用。

* 建议：仅开发模式（非打包）预置；或首次启动随机生成并只提示一次。

### 9. 改密码不吊销旧 token；token 无注销接口



* 位置：`user-store.js:149-177`、`server.js:42`

* 问题：改密后旧 token 仍有效 7 天；无 "登出所有设备" 能力。

* 建议：session 记录 token 签发时间，改密时吊销该用户全部 token；加 `POST /api/logout`。

### 10. scryptSync 同步哈希阻塞事件循环



* 位置：`user-store.js:22-24`

* 问题：登录 / 注册峰值时同步 scrypt（约 50-100ms / 次）卡住整个服务，其他请求全部排队。

* 建议：改用 `scrypt` 异步版本（`node:crypto` 回调 / Promise），或 `crypto.pbkdf2`。

### 11. JSON 存储无原子写，损坏时静默重置可能覆盖丢数据



* 位置：`chat-store.js:34-36,48-51`、`user-store.js:82-85`

* 问题：`writeFileSync` 直接覆盖；中途崩溃 / 断电可能产生半截 JSON；下次读取失败返回空对象，**再有一次写操作即把原文件覆盖成空，历史数据永久丢失**。

* 建议：写文件采用 "临时文件 + rename 原子替换"，保留 `.bak`；读取失败时**拒绝写入**并告警，而不是返回空继续。

### 12. 消息 500 条 / 会话静默截断



* 位置：`chat-store.js:178`

* 问题：`slice(-500)` 直接把旧消息丢掉，用户无感知、无归档，聊天记录不可回溯。

* 建议：改**分页存储**（按 500 条一个分片文件）或 SQLite；前端消息区做滚动分页加载。

## P1・核心体验（直接影响日常使用）

### 13. 前端登录门禁不校验 token 是否过期



* 位置：`apps/web/index.html:371-379`

* 问题：localStorage 有 username 就放行；token 过期后各 API 陆续报 "失败"，用户不知道要重新登录（无统一 401 处理）。

* 建议：进入主界面先 `GET /api/me` 验证；任一 API 返回 401 时统一清理会话并跳转登录页。

### 14. WS 无心跳，半开连接不清理



* 位置：`server.js:743-787`

* 问题：网络异常（如断网 / 休眠）后 TCP 半开，服务端连接不触发 close，推送仍往死连接发；连接数膨胀。

* 建议：服务端每 30s ping，客户端 pong；超时未响应则 close 并清理 `wsClients`。

### 15. 文件传输上限 8MB，无分片 / 断点



* 位置：`server.js:537`、`index.html:1253`

* 问题：大文件发不了；网络差时整体失败重来。

* 建议：文件走**独立上传接口（multipart / 二进制流）+ 分片（如 2MB / 片）+ 合并**；消息只存元数据引用。

### 16. 消息搜索只有 "当前会话内本地过滤"



* 位置：`index.html:1316-1348`

* 问题：无法跨会话搜历史消息，用户想找 "某人发过的一句话" 做不到。

* 建议：后端加 `/api/search`（按关键词搜所有有权限的会话），前端加全局搜索入口。

### 17. 未读没有系统级提醒（托盘角标 / 通知）



* 位置：`desktop/main.js`（无通知）、`index.html:1519-1526`

* 问题：后台驻留时新消息只有客户端内 toast，最小化到托盘后完全无感知。

* 建议：Electron `Notification` 系统通知 + 托盘未读角标（badge）；消息到来时桌面弹出。

### 18. 无消息撤回 / 删除、无已读回执



* 位置：`chat-store.js`（无相关字段 / 接口）

* 问题：发错消息无法撤回；对方是否已读只能靠未读计数消失推断。

* 建议：消息加 `id` 与 `seq`；实现撤回（标记 deleted，双方界面显示 "已撤回"）；已读回执（最后已读时间）。

### 19. 删除好友后无聊天记录管理界面



* 位置：`chat-store.js:107-119`、`index.html:1437-1459`

* 问题：数据保留在服务器但没有任何入口查看 / 清理，长期堆积。

* 建议：删除好友时提供 "保留记录 / 同时清空记录" 选项；设置里加 "存储占用" 管理。

### 20. 服务器端口冲突与健康检查缺失



* 位置：`apps/server-app/main.js:86-106`

* 问题：3000 被占用时业务服务启动失败，但托盘照常显示 "运行中"；无任何提示。

* 建议：启动后探测 `/api/me` 健康检查，失败时托盘显示错误并可查看日志；端口被占时提示换端口或复用已有实例。

### 21. 内置插件种子与 "用户删除" 冲突



* 位置：`server-app/main.js:54`

* 问题：用户删掉内置插件后，重启 Server 又自动种回来（注释说 "不覆盖" 但删除后 pack 不存在会重建）。

* 建议：`.meta` 记录 `deletedByUser: true`，种子跳过已删除项；或内置插件不做进市场。

## P2・功能增强（让软件更像 "产品"）

### 22. 资料设置不完整：无法改头像 / 昵称



* 位置：`user-store.js`（无更新接口）、`index.html` 设置页（只展示）

* 问题：注册时传错头像 / 名字后永远改不了，只能重新注册。

* 建议：`POST /api/account/profile`（displayName + avatar），设置页加编辑表单。

### 23. 插件市场无 "更新" 机制



* 位置：`index.html:676-710`、`desktop/main.js:184-200`

* 问题：同名 id 重新上传后客户端无版本比较，重复下载覆盖安装，无升级提示。

* 建议：本地已装记录版本，市场项版本更高时卡片显示 "更新"；插件元数据加 `updatedAt`。

### 24. 插件只有 "卸载 = 删除目录"，无启用 / 禁用开关



* 位置：`desktop/main.js:201-209`

* 问题：用户想暂时关掉插件又不想删。

* 建议：本地插件加 `.disabled` 标记，设置页可启停；停用后侧栏入口消失。

### 25. 客户端设置文件在 C 盘 userData



* 位置：`desktop/main.js:27`（`app.getPath("userData")/settings.json`）

* 问题：与 "数据不占 C 盘" 目标不一致（插件数据在 exe 旁，设置却在 C 盘）。

* 建议：设置文件移到 exe 旁 `data/settings.json`（与插件同目录）。

### 26. 消息区无分组时间、无滚动加载



* 位置：`index.html:1116-1148`（每条消息都渲染时间）、`server.js`（全量返回）

* 问题：连续多条消息每条都显示时间，视觉噪点；历史消息一次全量拉取。

* 建议：同 5 分钟内消息只显示首条时间（会话顶部置顶日期）；`/api/messages?before=` 分页。

### 27. 无在线状态、无 "输入中" 提示



* 位置：`server.js` WS 只做推送，无状态广播

* 问题：不知道对方是否在线；看不到对方正在输入。

* 建议：WS 广播 `presence`（在线 / 离线）；输入框 `typing` 事件（节流 2s）。

### 28. 无通知声音 / 消息提示音



* 位置：`index.html`（无音频）

* 问题：收到消息完全静默（除 toast）。

* 建议：Web Audio 生成轻提示音（不依赖外部资源），设置页可开关。

### 29. 会话列表无置顶 / 分组



* 位置：`index.html:967-1017`

* 问题：只能按最后消息时间排序，无法置顶重要会话。

* 建议：会话加 `pinned` 标记，置顶优先排序；支持拖拽置顶。

### 30. Server 无日志轮转



* 位置：`server-app/main.js:102`（`server.log` 单文件）

* 问题：日志无限增长占满磁盘。

* 建议：按天 / 按 5MB 轮转，保留最近 7 份。

## P3・工程治理（长期健康）

### 31. 无任何自动化测试



* 问题：后端纯函数（user-store/chat-store/ 插件链路）可测但未测；前端无冒烟测试。

* 建议：node:test 给 store 层写单测（含数据损坏 / 并发场景）；前端保持截图冒烟（已有 `_shots/finalshot.py` 套路）。

### 32. index.html 已 1540+ 行，单文件难维护



* 问题：全部视图 / 逻辑堆在一个文件，后续加功能极易互相踩。

* 建议：按 "登录 / 会话栏 / 聊天区 / 通讯录 / 设置 / 插件市场" 拆模块（原生 ES modules 或轻量构建），沿用 `theme.css`/`chat.css` 的拆分思路。

### 33. 无配置化



* 位置：`server.js:35-37`（全部靠 env）

* 问题：端口 / 数据目录 / 7za 路径 / 文件上限都写死或只靠环境变量，部署不友好。

* 建议：`data/server.config.json`（端口、上传上限、CORS 白名单、插件限制），env 优先。

### 34. 打包产物约 180MB / 个



* 问题：electron 全量三平台二进制，体积大。

* 建议：`electron-builder` + asar（已用）+ 去掉调试符号；评估 NSIS 单文件安装包；后续可考虑 Tauri（README 已列为备选）。

### 35. 无 CI / 无自动打包



* 问题：每次手工 electron-packager。

* 建议：GitHub Actions 按 tag 自动打包双 exe 并上传 release。

### 36. 前端错误处理零散、多处静默 catch



* 位置：`index.html` 多处 `.catch(function () {})`

* 问题：后端未启动 / 接口失败时用户看到空白或 "无反应"，无法定位。

* 建议：统一 fetch 封装（错误 toast + 401 跳登录 + 重试）；页面级 "服务器离线" 横幅。
